TASK: Implement secure “Forgot password” for SaaS users (new_users) with Resend email delivery. Must be i18n-ready (DE/EN) and must NOT break existing auth. Keep changes minimal and production-grade.

NON-NEGOTIABLES
- No user enumeration: responses must not reveal if an email exists.
- Tokens must be single-use, time-limited, and stored hashed.
- Rate limit requests per IP and per email.
- Do NOT change legacy trip-password login flows.
- Must work for web and iOS wrapper (links open in browser; return handled via existing /ios/return).
- App testing ON: add a manual test checklist and (if feasible) a small unit test for token verification.

ENV VARS (add but do not hardcode secrets)
- RESEND_API_KEY (required)
- EMAIL_FROM (required) e.g. "CrewLog <noreply@crewlog.app>"
- APP_BASE_URL (already exists; used to build reset links)
- SUPPORT_EMAIL (optional)

STEP 1 — Database schema
Add a new table for reset tokens (or SQLAlchemy model + alembic migration):

password_reset_tokens:
- id (serial PK)
- user_id (FK -> new_users.id)
- token_hash (varchar, indexed, unique)
- created_at (timestamp)
- expires_at (timestamp)
- used_at (timestamp nullable)
- request_ip (varchar nullable)
- user_agent (varchar nullable)

Constraints:
- token_hash unique
- expires_at required

STEP 2 — Token generation & hashing
Create helper functions:
- generate_reset_token() -> raw token (URL-safe, high entropy)
- hash_token(raw) -> token_hash (use SHA-256 or werkzeug generate_password_hash; prefer SHA-256 + constant-time compare)
Store ONLY token_hash. Never store raw token.

Expiry:
- 60 minutes default.

STEP 3 — Resend email sender
Create resend_mailer.py:
- send_password_reset(email, reset_url, locale)
Use Resend API with simple HTML + plain text fallback.
Email content must be localized (DE/EN) using templates or locale strings.

Do NOT include marketing content.
Subject examples:
- EN: “Reset your CrewLog password”
- DE: “CrewLog Passwort zurücksetzen”

STEP 4 — Routes (SaaS auth only)
Add routes:

GET /forgot-password
- Shows form: email input
- Language toggle works (existing i18n)
- Always shows neutral text

POST /forgot-password
- Rate-limited (per IP and per email)
- If email exists in new_users:
  - create token record
  - email reset link: {APP_BASE_URL}/reset-password?token=...
- Always return same response: “If the email exists, we sent a link.”

GET /reset-password?token=...
- Validate token_hash exists, not expired, not used
- Show new password form
- If invalid: show friendly error + link back to forgot-password

POST /reset-password
- Validate token again
- Set new_users.password_hash using existing werkzeug generate_password_hash style
- Mark token used_at
- Optionally revoke other active reset tokens for same user (set used_at)
- Redirect to login with success message

STEP 5 — Security hardening
- No user enumeration (always same response on forgot)
- Rate limiting:
  - 5 requests / hour / IP
  - 5 requests / hour / email
- Constant-time compare for token hashes
- Log to audit log (existing audit system) event type: PASSWORD_RESET_REQUEST, PASSWORD_RESET_SUCCESS (no raw token)
- Ensure CSRF protections apply as per existing system

STEP 6 — i18n
Add locale keys in de.json and en.json for:
- forgot password page labels/help text
- reset password page labels/help text
- success/error messages
- email subject + body strings (or template blocks)
Fall back to DE if missing.

STEP 7 — UI integration
- Add “Forgot password?” link to SaaS login page only.
- Do not add it to legacy trip login.

STEP 8 — Testing / Verification
Provide:
- Manual test checklist (DE and EN)
- Verify:
  - unknown email returns same message
  - known email sends email (mock in dev if needed)
  - token expires after 60 minutes
  - token single-use
  - rate limiting blocks abuse
  - password updated can log in via /login-saas
If feasible, add a small test for token validation logic.
